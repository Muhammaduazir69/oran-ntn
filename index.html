What oran-ntn does

oran-ntn is an ns-3 module that brings an O-RAN control plane to non-terrestrial network simulations, with E2 and A1 control loops running over a measured NR NTN cell. RIC placement (on board a satellite, on a HAPS, at a ground gateway or in the cloud) is an experiment variable whose E2 latency follows the live slant geometry.

Accompanying studySizing Intent Leases and Placing Near-Real-Time Control for O-RAN on LEO Satellites With Intermittent Feeder Links. Code and data are in this repository.

What it models

Where a RAN Intelligent Controller sits decides how stale its view is when a decision lands, and whether a satellite can still act when its feeder link is down. oran-ntn makes this measurable. An NR NTN cell on an SGP4 orbit, built by the ntn-traffic helper, supplies per-UE SINR and TBLER that are packed into E2SM-KPM indications under 3GPP TS 28.552 names, each row tagged with its provenance. The E2 node sends each indication one feeder delay up to the Near-RT RIC, optionally aligned to the 100 ms RIC tick, and buffers indications during a feeder outage while a Space RIC on the satellite takes over in autonomous mode. xApps decide, a conflict manager resolves contention, and E2SM-RC actions travel back to registered actuators such as a handover trigger or a beam loss model on the live channel. The next KPM report shows whether the action changed the radio.

The module has a real-time RIC tier on the satellite that refuses loop periods of 10 ms or more, A1 policy management with intent leases that fall back to a safe intent, a contact plan, cross-domain SMO analytics (NWDAF, transport path controller), and O-RAN WG4 fronthaul split options 2, 7.2a, 7.2b and 8 checked against the measured feeder delay. Platform classes (UAV, HAP, LEO, MEO, GEO), functional role switching from RU to full gNB, transparent and regenerative payloads after 3GPP TR 38.821, and ONNX-based inference xApps with a heuristic fallback are included. In simulation, E2 is a delay-modeled ns-3 header rather than ASN.1 APER over SCTP, and O1 is not modeled.

O-RAN E2SM-KPMKPI indications built from measured per-UE SINR and TBLER
O-RAN E2SM-RC (including Style 3)Control actions such as BEAM_SWITCH and HANDOVER_TRIGGER
O-RAN E2SM-CCCService model behind the service model registry
O-RAN A1 policyPolicy types with versioning, acknowledgement and intent leasing
O-RAN WG2 and WG3 architectureNon-RT and Near-RT RIC architecture and conflict mitigation

Install

Every module ships in the ready-built container image of the toolkit (version 3.0.1):

docker pull uzairdocker69/ns3-ntn-toolkit:latest
docker run --rm -it uzairdocker69/ns3-ntn-toolkit:latest bash

To build from source, clone ns3-ntn-toolkit, which vendors this module under contrib/, or follow the README of this repository (branch oran-ntn-v4).
